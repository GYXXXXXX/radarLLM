# radar_detect 项目报告

## 1. 项目定位

`radar_detect` 是一个基于 FMCW-MIMO 雷达的二维连续场景仿真工程，核心目标是为雷达目标识别、目标/干扰物区分、多目标关系建模、轨迹预测等任务提供可控的仿真数据。

工程当前包含两部分：

- MATLAB 数据生成代码：负责构造场景、轨迹、信号和标签；
- 已生成的数据集：`fmcw_traj_dataset/`，包含 `.mat` 场景文件、`index.csv` 场景索引和 PNG 可视化结果。

从任务角度看，这个工程不是传统检测数据集，而是一个“雷达原始观测 + 多层真值标签”的时序建模数据集。

## 3. 数据生成逻辑

### 3.1 场景与时间轴

- 每个场景固定 `48` 帧；
- 帧率 `10 Hz`；
- 场景总时长 `4.8 s`；
- 雷达位于二维原点 `[0, 0]`；
- 雷达朝向 `+x` 方向；
- 有效探测区域为 `5 m ~ 100 m`、前向 `±60°` 扇形。

### 3.2 目标与干扰物

真实目标类别共 `4` 类：

- `T1_slow_smooth`：慢速、平滑、RCS 强；
- `T2_uav_agile`：灵活机动、带模拟转子微多普勒；
- `T3_pedestrian`：低速、带模拟步态微多普勒；
- `T4_fast_maneuver`：速度更快、轨迹曲率更大。

干扰物类别共 `2` 类：

- `I1_false_reflector`：假目标/杂波反射体；
- `I2_wideband_jammer`：宽带干扰源。

### 3.3 多目标关系

同一场景的真实目标不是完全独立采样，而是带有关系约束：

- `formation`
- `crossing`
- `leader_follower`
- `converging`

这种设计使数据不仅适合单目标分类，也适合多目标协同建模和关系感知预测。

### 3.4 clean 版本约束

当前版本是 clean dataset，最重要的规则是：

- 所有真实目标在 `48` 帧内全程可见；
- 干扰物不要求全程可见；
- 真实目标轨迹连续、平滑；
- 场景关系明确；
- 训练阶段再决定输入帧和预测帧划分。

这意味着它非常适合做“输入观测与标签强对应”的监督学习实验，但与真实世界的复杂性仍有差距。

## 4. 雷达信号模型

### 4.1 雷达参数

默认雷达参数如下：

| 参数 | 值 |
| --- | --- |
| 载频 `fc` | `77 GHz` |
| 带宽 `B` | `150 MHz` |
| chirp 时长 `Tc` | `25 us` |
| ADC 采样率 `Fs` | `10 MHz` |
| fast-time 采样点 `Nfast` | `128` |
| 每帧 chirp 数 `Nchirp` | `32` |
| 接收阵元数 `Nrx` | `8` |
| 场景帧数 `Nframes` | `48` |

### 4.2 IQ 与 RD

每个场景保存两类主要观测：

- 原始复数 `iq`；
- 天线能量融合后的 `rdMap`。

默认 MATLAB 维度为：

```text
iq    : [128, 32, 8, 48]
rdMap : [128, 32, 48]
```

含义分别是：

- `iq`：`[fast-time, chirp, rx, frame]`
- `rdMap`：`[range_bin, doppler_bin, frame]`

其中：

- `iq` 保留距离、速度、角度相关信息，更适合二维轨迹预测与精细识别；
- `rdMap` 是二维 FFT 后的功率图，更适合图像式可视化与轻量模型输入，但角度信息弱于多通道 IQ。

### 4.3 目标信号差异

生成代码中，不同目标类别通过多散射中心、RCS、附加多普勒边带等方式编码到信号中：

- UAV 类有明显转子边带；
- 行人类有步态微多普勒；
- 高机动目标的多普勒变化更剧烈；
- 假目标类存在相位和多普勒不稳定；
- 宽带干扰类不服从常规点目标模型。

因此，这个数据集的标签差异并非只体现在轨迹几何上，也体现在频谱结构上。

## 5. 数据集结构分析

### 5.1 单个场景文件结构

每个 `scene_xxxxxx.mat` 文件包含：

- `iq`
- `rdMap`
- `gt`
- `meta`
- `p`

其中：

- `gt`：真值标签，含位置、速度、类别、可见性；
- `meta`：场景级标签，如目标数量、干扰物数量、关系类型；
- `p`：雷达和生成参数。

### 5.2 Python 读取时的一个关键点

场景文件由 MATLAB `-v7.3` 保存，本质是 HDF5。用 Python 读取时应注意：

- 推荐使用 `h5py`；
- MATLAB 按列主序保存，Python 中读出的数组维度顺序通常是反过来的；
- 例如 `iq` 在 HDF5 中会呈现为 `(48, 8, 32, 128)`，需要转置回 `(128, 32, 8, 48)`；
- `gt.name`、`meta.relationName` 这类字符串字段需要解码；
- `gt.targetObjectIndices` 等索引在 MATLAB 中是 1-based，Python 使用时应减 `1`。

### 5.3 索引文件统计

当前数据集共有 `50` 个场景，`index.csv` 统计结果如下：

- 真实目标数量均值：`2.72`
- 干扰物数量均值：`1.18`

真实目标数分布：

| 1 | 13 |

| 4 | 19 |

干扰物数分布：

关系类型分布：

### 5.4 数据特点总结

这个数据集具有以下结构性特点：

1. 时间连续性强：每个场景是完整 `48` 帧连续序列；
2. 标签层次清晰：同时有物体级、场景级和信号级信息；
3. 目标可见性好：真实目标不会出现“不可见仍要求预测”的矛盾；
4. 干扰建模存在差异：不仅是轨迹干扰，还包含宽带干扰；
5. 关系建模明确：适合研究多目标相互作用；
6. 数据规模中等偏小：当前 `50` 个场景更适合原型验证，而非大规模深度模型训练。

## 6. 优势与局限

### 6.1 优势

- IQ、RD、轨迹真值配套齐全；
- 目标类别与干扰物类别区分明确；
- 适合作为轨迹预测和时序识别的教学/验证型数据；
- 多目标关系标签明确，便于研究 scene-level reasoning；
- MATLAB 生成逻辑清晰，容易扩展。

### 6.2 局限

- 当前只有 `50` 个场景，数据量明显偏小；
- 无真实环境中的复杂地物杂波、多径、遮挡；
- 没有 CFAR 检测结果、点云、RAD cube 等中间表征；
- 干扰模型仍偏简化；
- 真实目标类别与场景规模耦合较强，泛化压力测试不够充分。

## 7. 推荐可视化方向

相比现有 MATLAB 图，我更推荐用 Python 额外做以下几类可视化：

1. `轨迹 + RD` 联合面板：
   同时看二维轨迹与关键帧 RD，快速判断运动和频谱是否一致。
2. 运动学时间曲线：
   画 `range-time`、`azimuth-time`、`radial velocity-time`，更适合看关系类型和机动差异。
3. 原始 IQ 幅度/相位热图：
   观察原始复数信号随 chirp 和 fast-time 的纹理变化。
4. 场景动画：
   逐帧播放目标位置和对应 RD 图，直观展示演化过程。
5. 数据集统计图：
   画目标数、干扰物数、关系类型的分布柱状图，便于论文或汇报使用。

## 8. 机器学习任务设计建议

### 8.1 分类任务

可以做三层分类：

- 场景级分类：预测 `meta.relationName`
- 物体级二分类：真实目标 vs 干扰物
- 物体级多分类：`T1~T4` 或 `I1~I2`

推荐输入：

- 若重视识别性能：优先用多通道 `iq`
- 若重视实现简单：先用 `rdMap`

### 8.2 回归任务

可以做三类回归：

- 未来轨迹回归：预测未来 `x,y`
- 速度回归：预测未来 `vx, vy`
- 参数回归：预测 `range / azimuth / radial velocity`

推荐任务划分示例：

```text
输入: 前 32 帧
输出: 后 16 帧
```

### 8.3 建模建议

对于这个数据集，建议优先考虑“空间编码 + 时间编码”的两阶段架构：

- IQ/RD 编码器提取每帧空间特征；
- GRU / Temporal Convolution / Transformer 建模跨帧关系；
- 多任务头同时输出类别和未来轨迹。

更细的网络结构建议可结合本仓库中的 Python 可视化脚本和后续任务定义继续细化。

## 9. 结论

`radar_detect` 是一个结构清晰、标签完整、非常适合雷达时序学习原型验证的仿真工程。它的价值不在于“场景数很多”，而在于：

- 原始复数 IQ 可用于深层信号学习；
- 目标和干扰物设计有明确物理含义；
- 多目标关系标签适合时空建模；
- clean 版本便于搭建稳定的训练闭环。

如果后续要把它发展成更有研究价值的数据集，优先建议扩展三个方向：

1. 扩容场景数量；
2. 引入更真实的环境与检测不确定性；
3. 增加 Python 训练与评估基线，形成完整实验链路。
