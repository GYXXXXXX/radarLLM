# 认知雷达闭环仿真可视化系统技术说明

## 1. 系统概述

- 本系统用于展示海上认知雷达闭环场景，核心对象包括：
  - 岸基固定雷达；
  - 两艘己方移动舰船 `V-01`、`V-02`；
  - 两个动态目标 `T-01`、`T-02`；
  - 三部协同工作的雷达：岸基雷达、舰 01 雷达、舰 02 雷达。

- 系统目标是构建“感知、推理、决策、控制、可视化”的闭环链路：

```text
目标与平台运动仿真
-> 三雷达观测生成
-> 统一世界坐标融合
-> Transformer 轨迹预测与意图识别
-> LLM 态势推理与任务建议
-> 约束控制器生成雷达控制参数
-> 前端实时可视化展示
```

- 当前实现采用 Python 后端驱动前端界面。前端主要承担可视化与交互功能；后端负责仿真推进、轨迹融合、模型推理、LLM 决策和控制参数计算。

## 2. 系统组成

### 2.1 主要实体

- **岸基雷达**
  - 固定部署在海岸附近；
  - 承担广域搜索、目标发现和持续监视；
  - 为舰载雷达提供目标指示；
  - 参与多雷达融合与目标跟踪。

- **舰船 `V-01`**
  - 持续沿预设航路运动；
  - 搭载舰 01 雷达；
  - 主要承担近距精确跟踪；
  - 雷达原点随舰船位置同步更新。

- **舰船 `V-02`**
  - 持续沿另一条航路运动；
  - 搭载舰 02 雷达；
  - 从不同观测方位提供交叉确认；
  - 与岸基雷达、舰 01 雷达构成协同观测结构。

- **动态目标 `T-01` 与 `T-02`**
  - 均沿预设动态航迹运动；
  - 可通过界面切换当前协同跟踪目标；
  - 切换目标时三部雷达不会停止工作，而是共同转向新的重点目标。

### 2.2 雷达工作方式

- 三部雷达始终同时工作。
- 界面中的“岸基 / 舰01 / 舰02”仅用于切换当前查看的数据视角。
- 用户选择 `T-01` 或 `T-02` 后，后端会将该目标作为当前重点跟踪目标。
- 舰载雷达的波束原点绑定到舰船位置，因此舰船运动会直接影响雷达观测几何关系。

## 3. 后端闭环流程

- 每个仿真周期执行以下步骤：

```text
1. 更新舰船位置、速度和航向
2. 更新目标位置、速度和航向
3. 岸基雷达、舰 01 雷达、舰 02 雷达分别生成观测量
4. 将各雷达观测转换到统一世界坐标
5. 对同一目标的多雷达观测进行融合
6. 更新目标历史轨迹窗口
7. 调用 TrackIntentTransformer 进行预测与分类
8. 调用 LLM 或规则决策模块生成任务级建议
9. 约束控制器生成可执行雷达参数
10. 将闭环状态推送至前端可视化
```

- 该流程形成在线闭环：
  - 雷达观测影响目标轨迹估计；
  - 轨迹估计影响 Transformer 预测；
  - Transformer 输出影响 LLM 态势判断；
  - LLM 建议影响雷达控制模式；
  - 雷达控制结果反过来影响后续观测质量。

## 4. 观测模型与轨迹融合

### 4.1 单雷达观测特征

每部雷达对目标生成以下观测特征：

| 特征 | 含义 |
|---|---|
| `range` | 雷达到目标的测量距离 |
| `bearing` | 目标在世界坐标系下的方位角 |
| `localBearing` | 目标相对雷达平台航向的局部方位 |
| `rangeRate` | 目标相对雷达的径向速度 |
| `doppler` | 由径向速度换算得到的多普勒显示量 |
| `confidence` | 当前观测可信度 |
| `estimate.x / estimate.y` | 雷达观测转换后的目标位置估计 |

### 4.2 置信度影响因素

- 当前观测置信度主要由以下因素共同决定：
  - 目标是否位于雷达波束中心附近；
  - 目标距离是否处于有效探测范围内；
  - 目标是否为当前重点跟踪目标；
  - 场景中的感知扰动强度；
  - 海杂波对观测质量的影响。

- 波束越接近目标方向，观测置信度越高。
- 感知扰动越大，测距和测角误差越明显。
- 海杂波越强，显示信噪比越低。

### 4.3 统一世界坐标转换

- 岸基雷达和舰载雷达位于不同观测位置。
- 舰载雷达随舰船运动，其观测天然处于动态平台视角。
- 为使三部雷达的数据能够共同进入同一模型链路，后端将所有观测统一转换为世界坐标下的位置估计：

```text
世界坐标位置 = 雷达位置 + 方位角方向向量 × 测量距离
```

- 该处理是动态雷达复用轨迹模型的关键：
  - 模型输入不是雷达局部坐标系下的方位和距离；
  - 模型输入是统一世界坐标下的目标轨迹状态。

### 4.4 多雷达融合

- 同一目标在同一时刻会产生三组观测：
  - 岸基雷达观测；
  - 舰 01 雷达观测；
  - 舰 02 雷达观测。

- 后端根据观测置信度进行加权融合：

```text
融合位置 = 各雷达位置估计的置信度加权平均
```

- 融合结果进一步进入简化的预测-校正滤波过程，得到目标状态：

```text
[x, y, vx, vy]
```

- 当前融合方法属于轻量化 alpha-beta 滤波结构，适合仿真演示和闭环验证；工程化系统可进一步替换为 EKF、UKF、JPDA 或 MHT 等方法。

## 5. Transformer 感知模型

### 5.1 当前使用的模型类型

- 系统当前加载的模型为：

```text
TrackIntentTransformer
```

- 该模型输入为目标轨迹状态序列，而不是原始 IQ 数据。
- 模型权重对应的输入模式为：

```text
input_mode = track
```

### 5.2 模型输入

- 输入张量结构为：

```text
[B, K, Tin, 4]
```

| 维度 | 含义 |
|---|---|
| `B` | 批大小，在线推理中为 1 |
| `K` | 最大目标槽位数 |
| `Tin` | 输入历史帧数，当前为 24 |
| `4` | 每帧目标状态 `[x, y, vx, vy]` |

- `x`、`y` 表示统一世界坐标下的位置。
- `vx`、`vy` 表示统一世界坐标下的速度分量。
- 输入进入模型前会按训练配置进行标准化，以保持训练和在线推理的数据分布一致。

### 5.3 模型输出

| 输出 | 含义 |
|---|---|
| `state_pred` | 未来多帧目标状态预测 |
| `intent_logits` | 目标意图分类结果 |
| `threat_logits` | 威胁等级分类结果 |
| `objectness_logits` | 目标存在性评分 |
| `target_class_logits` | 目标类别分类结果 |

- 当前重点使用三类输出：
  - 未来轨迹预测；
  - 目标意图判断；
  - 目标威胁等级判断。

### 5.4 意图与威胁标签

- 意图标签包括：

| 标签 | 含义 |
|---|---|
| `benign_transit` | 常规通过 |
| `approach` | 接近 |
| `retreat` | 远离或撤离 |
| `loiter_patrol` | 盘旋或巡逻 |
| `intercept` | 拦截或高关注机动 |

- 威胁标签包括：

| 标签 | 含义 |
|---|---|
| `low` | 低威胁 |
| `guarded` | 警戒 |
| `elevated` | 威胁升高 |
| `high` | 高威胁 |

## 6. LLM 态势推理模块

### 6.1 模块位置

- LLM 位于 Transformer 之后、控制器之前：

```text
TrackIntentTransformer 输出
-> LLM 态势推理
-> 约束控制器
```

- LLM 不直接生成底层雷达控制量。
- LLM 负责生成任务级建议。
- 约束控制器负责将任务建议转换为可执行参数。

### 6.2 LLM 输入特征

LLM 接收的主要结构化信息包括：

| 特征 | 含义 |
|---|---|
| `target_id` | 当前分析目标 |
| `state` | 当前融合目标状态 |
| `intent` | Transformer 输出的意图标签 |
| `threat` | Transformer 输出的威胁等级 |
| `intent_confidence` | 意图置信度 |
| `threat_confidence` | 威胁置信度 |
| `predicted_range_delta` | 预测距离变化 |
| `predicted_track` | 未来轨迹预测序列 |
| `selected_target` | 当前重点跟踪目标 |

### 6.3 LLM 输出内容

LLM 输出结构化任务建议，主要字段包括：

| 字段 | 含义 |
|---|---|
| `final_intent` | 综合判断后的目标意图 |
| `priority` | 任务优先级 |
| `action` | 建议执行的任务动作 |
| `reason` | 态势判断依据 |
| `radar_guidance` | 对三部雷达的任务级建议 |
| `platform_guidance` | 对舰船平台站位或运动的建议 |

可选任务动作包括：

| 动作 | 含义 |
|---|---|
| `monitor` | 常规监视 |
| `increase_tracking_rate` | 提高跟踪频率 |
| `classify_and_shadow` | 分类识别并伴随监视 |
| `alert_and_allocate_tracker` | 告警并分配精跟资源 |

### 6.4 决策稳定性处理

- LLM 调用采用异步方式，避免阻塞仿真主循环。
- 当 LLM 尚未返回或调用异常时，系统使用规则决策作为 fallback。
- fallback 决策仍可输出任务动作和控制建议，保证闭环持续运行。
- LLM 输出会经过规范化处理，避免缺失字段或非法动作直接进入控制器。

## 7. 雷达约束控制器

### 7.1 控制器作用

- 控制器负责将任务级建议转换为三部雷达的可执行参数。
- 控制器同时考虑：
  - 目标预测位置；
  - 当前雷达位置；
  - LLM 建议动作；
  - 模型置信度；
  - 雷达自身参数约束；
  - 方位角变化速率限制。

### 7.2 控制器输出

| 参数 | 含义 |
|---|---|
| `beamAzimuth` | 当前波束方位角 |
| `beamWidth` | 当前波束宽度 |
| `dwell` | 当前驻留时间 |
| `rangeGate` | 当前距离门 |
| `desiredAzimuth` | 期望波束方位角 |
| `desiredWidth` | 期望波束宽度 |
| `desiredDwell` | 期望驻留时间 |
| `mode` | 当前控制模式 |
| `constraint` | 当前约束类型 |

### 7.3 控制动作与参数关系

| 任务动作 | 控制倾向 |
|---|---|
| `monitor` | 保持较宽波束和常规驻留时间 |
| `classify_and_shadow` | 适度收窄波束，提高分类稳定性 |
| `increase_tracking_rate` | 收窄波束并增加驻留时间，提高跟踪强度 |
| `alert_and_allocate_tracker` | 使用更窄波束和更长驻留时间，执行高优先级精跟 |

- 当模型置信度较低时，控制器会适当增大波束宽度并增加驻留时间，以增强目标重新捕获能力。
- 岸基雷达更偏向广域持续监视。
- 舰载雷达更偏向机动平台上的近距精确跟踪。

### 7.4 平滑控制机制

- 为避免目标切换时波束突变，控制器引入方位角速率约束。
- 波束方向按照最大转向速率逐步逼近期望方位。
- 波束宽度、驻留时间和距离门采用平滑插值更新。
- 因此，从 `T-01` 切换到 `T-02` 时，三部雷达应表现为连续转向，而非瞬时跳变。

## 8. 前端可视化字段说明

### 8.1 顶部状态区

| 字段 | 含义 |
|---|---|
| `BACKEND / DISCONNECTED` | 后端连接状态 |
| `后端模型` | 当前加载的后端模型类型 |
| `LLM` | 当前使用的推理模型或规则决策模式 |
| `周期` | 闭环仿真推进次数 |
| `时标` | 当前仿真时间 |
| `闭环` | 界面显示的闭环刷新频率 |

### 8.2 左侧交互区

- **数据视图**
  - 切换当前查看的雷达数据；
  - 不改变其他雷达的工作状态。

- **跟踪目标**
  - 切换当前重点跟踪目标；
  - 三部雷达共同调整到新的目标。

- **运行控制**
  - 控制仿真运行、暂停和状态复位。

- **环境参数**
  - `仿真速度`：影响仿真时间推进；
  - `海杂波`：影响信噪比和观测质量显示；
  - `感知扰动`：影响测距、测角和置信度。

- **显示层**
  - 控制波束、航迹和距离门是否显示。

### 8.3 地图显示区

- 地图显示内容包括：
  - 岸基雷达位置；
  - `V-01`、`V-02` 舰船位置；
  - `T-01`、`T-02` 目标位置；
  - 三部雷达的波束扇形；
  - 距离门和探测范围辅助线；
  - 平台与目标历史轨迹；
  - Transformer 预测轨迹。

### 8.4 右侧数据区

| 字段 | 含义 |
|---|---|
| `方位` | 当前雷达波束方位角 |
| `距离` | 当前雷达对目标的测量距离 |
| `置信度` | 当前雷达观测可信程度 |
| `SNR` | 当前信噪比显示值 |
| `波束宽度` | 当前雷达波束覆盖角宽 |
| `驻留时间` | 当前波束在目标方向的驻留时长 |
| `估计方位` | 感知结果中的目标方位 |
| `估计距离` | 感知结果中的目标距离 |
| `多普勒` | 目标相对径向运动信息 |
| `一致性` | 多雷达融合和模型判断的综合可信程度 |
| `意图` | Transformer 输出的目标意图 |
| `威胁` | Transformer 输出的威胁等级 |
| `态势说明` | LLM 或规则模块给出的判断依据 |
| `控制建议` | 当前任务动作与控制约束 |

### 8.5 IQ / Range-Doppler 面板

- 当前 IQ / Range-Doppler 面板用于展示雷达信号响应的可视化效果。
- 当前在线闭环真正输入 Transformer 的是融合后的 track 状态。
- 系统尚未将真实 MATLAB IQ 矩阵作为后端实时输入。
- 后续可通过增加 IQ 读取、检测和坐标转换模块，将真实 IQ 数据接入闭环。

## 9. 当前实现与边界

### 9.1 已实现能力

- 三雷达协同跟踪；
- 舰载雷达随舰船运动；
- `T-01` / `T-02` 目标切换；
- 多雷达观测生成；
- 世界坐标转换；
- 目标轨迹融合；
- TrackIntentTransformer 在线推理；
- LLM 任务级态势建议；
- 规则 fallback 决策；
- 约束控制器生成波束参数；
- 前端实时显示闭环状态。

### 9.2 当前限制

- 当前未直接接入真实 MATLAB IQ 数据流。
- 当前 IQ / Range-Doppler 面板主要为可视化表达。
- 当前多雷达融合为简化滤波结构。
- 当前 LLM 只输出任务级建议，不直接控制舰船真实运动。
- 当前二维场景坐标用于仿真展示，不等价于真实海图坐标。

## 10. 后续扩展方向

- **真实 IQ 接入**
  - 增加 `.mat` 或实时 IQ 数据读取；
  - 完成 Range-Doppler 处理与目标检测；
  - 将检测结果转换为统一世界坐标轨迹。

- **动态雷达坐标建模**
  - 引入舰船 GPS/惯导信息；
  - 考虑雷达安装偏角；
  - 完成雷达坐标系、舰体坐标系与世界坐标系转换。

- **多目标跟踪增强**
  - 使用 EKF、UKF、JPDA 或 MHT 替代当前简化滤波；
  - 增强复杂多目标场景下的航迹稳定性。

- **LLM 决策增强**
  - 增加任务区域、禁航区、平台能力等上下文；
  - 增加严格 JSON schema 校验；
  - 将平台建议接入舰船路径规划模块。

- **控制器增强**
  - 引入雷达资源调度；
  - 增加多目标波束分配策略；
  - 建立跟踪精度与资源消耗之间的优化模型。

## 11. 汇报总结

- 本系统实现了一个后端驱动的认知雷达闭环仿真原型。
- 系统以三雷达协同观测为基础，将动态平台观测转换为统一世界坐标轨迹。
- TrackIntentTransformer 负责未来轨迹预测、意图识别和威胁判断。
- LLM 根据模型输出和预测轨迹生成任务级态势建议。
- 约束控制器将任务建议转换为可执行的波束方向、波束宽度、驻留时间和距离门参数。
- 前端以实时可视化方式展示多雷达协同跟踪、目标预测、态势推理和控制闭环过程。
- 当前系统已形成完整闭环框架，可作为后续接入真实 IQ 数据、增强多目标跟踪和扩展智能决策控制的基础。
