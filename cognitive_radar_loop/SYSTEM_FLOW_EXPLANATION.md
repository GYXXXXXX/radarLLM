# 认知雷达闭环系统整体流程说明

## 1. 核心结论

- 当前系统是一个后端实时推进的闭环仿真系统，不是预录制动画。
- 目标 `T-01`、`T-02` 的真实运动轨迹由预设航路点和时间周期生成。
- 三部雷达不会直接生成目标真实轨迹，而是对目标进行带误差的观测。
- Transformer 使用的是多雷达融合后的目标轨迹状态。
- LLM 使用 Transformer 输出和目标态势信息，生成任务级建议。
- 雷达控制器将 LLM 的任务建议转换为具体雷达控制参数。

整体关系为：

```text
预设目标运动
-> 三雷达观测
-> 多雷达融合
-> Transformer 轨迹预测与意图/威胁判断
-> LLM 任务级态势推理
-> 雷达控制器生成可执行控制参数
-> 三雷达更新波束
-> 下一周期继续观测
```

## 2. 目标轨迹如何生成

### 2.1 真实目标轨迹

当前系统中，目标真实位置不是由 Transformer 或 LLM 生成，而是由后端预设航路生成。

每个目标包含：

- 一组航路点；
- 一个运动周期；
- 当前仿真时间。

后端根据仿真时间计算目标当前位于哪两个航路点之间，并进行平滑插值，得到目标当前位置：

```text
目标位置 = 航路点之间的时间插值结果
```

由于时间会按照周期取模，因此目标会沿预设航线循环运动。

### 2.2 目标速度

目标速度不是单独设定的固定值，而是由相邻两个仿真时刻的位置变化计算得到：

```text
vx = (当前 x - 上一时刻 x) / dt
vy = (当前 y - 上一时刻 y) / dt
```

因此，目标状态可以表示为：

```text
[x, y, vx, vy]
```

其中：

- `x, y` 表示目标在世界坐标系下的位置；
- `vx, vy` 表示目标在世界坐标系下的速度。

## 3. 三部雷达如何参与观测

### 3.1 三雷达并行工作

系统中共有三部雷达：

- 岸基雷达；
- 舰 01 雷达；
- 舰 02 雷达。

三部雷达始终同时工作。界面中切换“岸基 / 舰01 / 舰02”只是切换数据查看视角，不会关闭其他雷达。

### 3.2 雷达观测内容

每部雷达对当前场景中的目标生成观测量，包括：

| 观测量 | 含义 |
|---|---|
| `range` | 雷达到目标的距离 |
| `bearing` | 目标在世界坐标系下的方位角 |
| `localBearing` | 目标相对雷达平台航向的局部方位 |
| `rangeRate` | 目标相对雷达的径向速度 |
| `doppler` | 由径向速度得到的多普勒显示量 |
| `confidence` | 该雷达本次观测的可信度 |
| `estimate.x / estimate.y` | 该雷达估计出的目标世界坐标位置 |

### 3.3 动态雷达的坐标统一

岸基雷达是固定的，舰载雷达随舰船移动。为了让三部雷达的数据可以共同使用，后端会把每个雷达的观测转换到统一世界坐标系。

概念上可以表示为：

```text
目标世界坐标估计 = 雷达世界坐标 + 方位方向向量 × 测量距离
```

这样，来自岸基雷达、舰 01 雷达和舰 02 雷达的观测都可以统一表示为目标位置估计。

## 4. 多雷达融合做了什么

三部雷达对同一个目标会得到三组观测。后端根据观测置信度进行融合。

基本思想是：

```text
置信度高的雷达观测权重大
置信度低的雷达观测权重小
```

融合后得到目标的统一状态：

```text
[x, y, vx, vy]
```

这个融合轨迹才是 Transformer 的输入基础。

因此，当前系统不是：

```text
每个雷达各自调用一个 Transformer
```

而是：

```text
三部雷达先观测
-> 后端融合成统一轨迹
-> 统一轨迹输入 Transformer
```

## 5. Transformer 输入和输出

### 5.1 Transformer 输入

当前系统使用的模型是：

```text
TrackIntentTransformer
```

它的输入不是原始 IQ 数据，而是目标历史轨迹窗口：

```text
[x, y, vx, vy]
```

模型输入结构为：

```text
[B, K, Tin, 4]
```

含义如下：

| 维度 | 含义 |
|---|---|
| `B` | 批大小，在线服务中为 1 |
| `K` | 目标槽位数 |
| `Tin` | 输入历史帧数，当前为 24 |
| `4` | 每帧状态 `[x, y, vx, vy]` |

### 5.2 Transformer 输出

Transformer 输出主要包括：

| 输出 | 含义 |
|---|---|
| `state_pred` | 未来多帧目标轨迹预测 |
| `intent_logits` | 目标意图分类结果 |
| `threat_logits` | 威胁等级分类结果 |
| `objectness_logits` | 目标存在性评分 |
| `target_class_logits` | 目标类别分类结果 |

在当前闭环中，重点使用以下三类信息：

```text
未来轨迹预测
目标意图
目标威胁等级
```

### 5.3 未来轨迹预测

模型会预测目标未来若干帧状态：

```text
未来第 1 帧: [x, y, vx, vy]
未来第 2 帧: [x, y, vx, vy]
...
未来第 8 帧: [x, y, vx, vy]
```

该预测结果用于判断目标未来运动趋势，并为后续雷达波束提前指向提供依据。

### 5.4 意图与威胁

Transformer 会输出目标意图，例如：

- `approach`：接近；
- `retreat`：远离；
- `loiter_patrol`：盘旋或巡逻；
- `intercept`：拦截或高关注机动。

Transformer 也会输出威胁等级，例如：

- `low`；
- `guarded`；
- `elevated`；
- `high`。

这些结果会进入 LLM 态势推理模块。

## 6. LLM 大模型做了什么

### 6.1 LLM 的输入

LLM 接收的是结构化态势信息，而不是原始雷达信号。

主要输入包括：

| 输入 | 含义 |
|---|---|
| 当前目标编号 | 例如 `T-01` 或 `T-02` |
| 当前目标状态 | 融合后的 `[x, y, vx, vy]` |
| 预测轨迹 | Transformer 输出的未来轨迹 |
| 意图判断 | Transformer 输出的意图 |
| 威胁等级 | Transformer 输出的威胁 |
| 置信度 | 意图和威胁判断的可信度 |
| 当前跟踪目标 | 系统当前重点跟踪对象 |

### 6.2 LLM 的输出

LLM 输出任务级建议，而不是底层雷达控制参数。

输出内容包括：

| 输出 | 含义 |
|---|---|
| `final_intent` | 综合判断后的目标意图 |
| `priority` | 任务优先级 |
| `action` | 建议执行的任务动作 |
| `reason` | 态势判断说明 |
| `radar_guidance` | 对三部雷达的任务建议 |
| `platform_guidance` | 对舰船平台的运动或站位建议 |

典型任务动作包括：

| 动作 | 含义 |
|---|---|
| `monitor` | 常规监视 |
| `increase_tracking_rate` | 提高跟踪频率 |
| `classify_and_shadow` | 分类识别并伴随监视 |
| `alert_and_allocate_tracker` | 告警并分配精跟资源 |

### 6.3 LLM 与 Transformer 的关系

Transformer 更偏向数值感知和模式识别：

```text
目标未来怎么走
目标当前像什么意图
威胁等级大致是多少
```

LLM 更偏向任务解释和协同建议：

```text
为什么需要提高跟踪
哪部雷达应承担精跟
是否需要保持交叉观测
是否需要加强警戒
```

## 7. 雷达控制器是什么

### 7.1 定义

这里的雷达控制器不是独立硬件设备，而是后端中的一个控制逻辑模块。

在当前系统中，它对应：

```text
ConstraintController
```

它位于 LLM 之后、雷达状态更新之前。

### 7.2 控制器为什么需要存在

LLM 的输出是任务级建议，例如：

```text
提高跟踪频率
保持交叉观测
执行精确跟踪
```

但真实雷达不能直接执行这类自然语言或高层策略。雷达需要的是具体数值参数，例如：

```text
波束指向多少度
波束宽度多少度
驻留时间多少毫秒
距离门设置到多远
```

因此需要一个控制器把任务建议转换为可执行参数。

### 7.3 控制器使用

控制器在每个后端仿真周期都会被调用。

流程位置如下：

```text
三雷达观测
-> 多雷达融合
-> Transformer 推理
-> LLM 决策
-> 控制器更新三部雷达参数
-> 前端显示新状态
```

### 7.4 控制器输入

控制器主要读取：

| 输入 | 来源 |
|---|---|
| 当前雷达位置 | 岸基固定位置或舰船当前位置 |
| 当前目标融合状态 | 多雷达融合结果 |
| 未来预测轨迹 | Transformer 输出 |
| 任务动作 | LLM 输出或规则 fallback |
| 意图置信度 | Transformer 输出 |
| 仿真步长 | 后端仿真循环 |

### 7.5 控制器输出

控制器输出三部雷达的具体控制量：

| 控制量 | 含义 |
|---|---|
| `beamAzimuth` | 雷达波束当前方位角 |
| `beamWidth` | 雷达波束宽度 |
| `dwell` | 波束驻留时间 |
| `rangeGate` | 距离门 |
| `desiredAzimuth` | 期望指向角 |
| `desiredWidth` | 期望波束宽度 |
| `desiredDwell` | 期望驻留时间 |
| `mode` | 当前控制模式 |
| `constraint` | 控制约束类型 |

### 7.6 控制器如何影响三部雷达

不同任务动作对应不同控制策略：

| LLM 动作 | 控制器行为 |
|---|---|
| `monitor` | 保持较宽波束，执行常规监视 |
| `classify_and_shadow` | 适度收窄波束，增强分类稳定性 |
| `increase_tracking_rate` | 收窄波束并增加驻留时间，提高跟踪强度 |
| `alert_and_allocate_tracker` | 使用更窄波束和更长驻留时间，执行高优先级精跟 |

控制器还会根据每部雷达的位置分别计算波束方向。

三雷达观测
-> 多雷达融合
-> Transformer 预测与分类
-> LLM 任务建议
-> 雷达控制器生成具体参数
-> 三部雷达更新波束

因此，同一个目标对三部雷达的方位角不同，三部雷达最终的波束指向也不同。

## 8. 闭环如何形成

当前系统的闭环关系可以概括为：

```text
目标运动产生新位置
-> 雷达根据当前波束状态进行观测
-> 观测结果影响融合轨迹质量
-> 融合轨迹输入 Transformer
-> Transformer 预测未来轨迹和目标意图
-> LLM 根据预测结果生成任务建议
-> 控制器调整雷达波束
-> 新波束影响下一周期观测质量
```

这就是系统中的认知雷达闭环。

其中：

- 目标真实轨迹由预设程序生成；
- 雷达观测受波束指向、距离、扰动和杂波影响；
- Transformer 负责预测和分类；
- LLM 负责任务级推理；
- 控制器负责数值化执行；
- 前端负责展示闭环状态。

## 9. 需要特别区分的内容

### 9.1 不是目标由 AI 自动生成

当前目标真实路线是预设的。AI 模型并不负责生成真实目标路线。

AI 模型负责根据观测融合后的历史轨迹预测未来轨迹。

### 9.2 不是每部雷达各自调用一个 Transformer

当前实现中，三部雷达先各自观测，然后后端进行融合，再将融合轨迹输入一个 TrackIntentTransformer。

### 9.3 LLM 不直接控制雷达

LLM 输出的是任务级建议。真正的雷达参数由约束控制器生成。

### 9.4 控制器是闭环执行层

控制器是连接“大模型任务建议”和“雷达可执行参数”的关键模块。

如果没有控制器，LLM 的文字或高层动作无法稳定、安全地转换为波束方向、波束宽度和驻留时间。

## 10. 简化汇报表述

可以将当前系统概括为：

```text
系统首先通过预设航路生成动态目标和移动舰船；
三部雷达分别从不同位置对目标进行观测；
后端将多雷达观测转换到统一世界坐标并进行融合；
融合后的历史轨迹输入 TrackIntentTransformer，得到未来轨迹、目标意图和威胁等级；
LLM 基于这些结构化结果生成任务级态势建议；
约束控制器将建议转换为三部雷达的波束方向、波束宽度、驻留时间和距离门；
更新后的雷达状态继续影响下一周期观测，从而形成认知雷达闭环。
```

## 11. 控制器输出结果解释汇报

### 11.1 输出结果总体含义

页面右侧“控制器影响三部雷达”面板展示的是雷达闭环控制器对岸基雷达、舰 01 雷达和舰 02 雷达生成的可执行控制结果。

这些数值由后端 `ConstraintController` 根据目标预测结果、LLM 任务动作、任务优先级、意图置信度和每部雷达自身位置实时计算得到。

整体生成关系为：

```text
多雷达观测
-> 融合目标状态
-> Transformer 预测未来轨迹、意图和威胁等级
-> LLM 生成任务动作与优先级
-> ConstraintController 转换为雷达控制参数
-> 前端显示三部雷达的控制效果
```

因此，该面板的作用是把“大模型建议”进一步解释为雷达系统真正能够执行的数值命令。

### 11.2 面板中每个输出项的含义

| 显示项 | 示例 | 含义 |
|---|---:|---|
| `波束` | `24.7° / 34.0°` | 当前雷达实际波束状态。前一个值是当前波束方位角，后一个值是当前波束宽度。 |
| `目标` | `24.7° / 34.0°` | 控制器希望雷达达到的目标状态。前一个值是目标方位角，后一个值是目标波束宽度。 |
| `强度` | `55%` | 归一化跟踪强度指标，用于表示当前控制策略的跟踪聚焦程度。它不是雷达发射功率。 |
| `速度` | `36.0°/s` | 波束最大转向速度，表示雷达波束每秒最多允许转动多少度。 |
| `驻留` | `159→159 ms` | 当前驻留时间到目标驻留时间。驻留时间越长，该方向信号积累越充分，但扫描其它方向会变慢。 |
| `距离门` | `100.9 km` | 控制器设置的距离搜索窗口，用于约束雷达重点关注的目标距离范围。 |

面板顶部的文本如：

```text
classify_and_shadow / bounded_slew
```

含义如下：

| 字段 | 含义 |
|---|---|
| `classify_and_shadow` | LLM 或规则层给出的任务动作，表示“分类识别并伴随监视”。 |
| `bounded_slew` | 控制器执行约束，表示波束不能瞬间跳转，而是按最大转向速度逐步转向。 |

### 11.3 各输出值如何生成

#### 11.3.1 任务动作如何进入控制器

Transformer 首先输出目标未来轨迹、意图和威胁等级。LLM 基于这些结构化结果生成任务动作，例如：

```text
monitor
classify_and_shadow
increase_tracking_rate
alert_and_allocate_tracker
```

如果在线 LLM 不可用，系统会使用规则 fallback，根据意图和威胁等级生成同类任务动作。

控制器读取该动作后，将其转换成基础波束宽度和驻留时间：

| LLM 动作 | 目标波束宽度 | 目标驻留时间 | 控制意图 |
|---|---:|---:|---|
| `monitor` | `30°` | 雷达基础驻留时间 | 常规监视，保持较宽搜索范围。 |
| `classify_and_shadow` | `20°` | `135 ms` | 适度收窄波束，增强分类稳定性。 |
| `increase_tracking_rate` | `14°` | `165 ms` | 更集中地跟踪目标，提高刷新和跟踪强度。 |
| `alert_and_allocate_tracker` | `10°` | `210 ms` | 高优先级精跟，使用更窄波束和更长驻留。 |

岸基雷达、舰 01 和舰 02 的基础驻留时间不同：

| 雷达 | 基础驻留时间 |
|---|---:|
| 岸基雷达 | `104 ms` |
| 舰 01 雷达 | `86 ms` |
| 舰 02 雷达 | `90 ms` |

#### 11.3.2 波束方位角如何生成

控制器不会直接照抄当前目标位置，而是优先使用 Transformer 预测轨迹中的未来点。

生成方式为：

```text
预测目标位置 = Transformer 未来轨迹中的第 3 个预测点
目标方位角 = radar 到预测目标位置的几何方位角
```

由于三部雷达位置不同，同一个目标相对三部雷达的方位角也不同，所以三部雷达的目标波束方位会分别计算。

#### 11.3.3 波束宽度如何生成

控制器先根据任务动作得到基础波束宽度，再根据置信度和雷达约束修正。

如果意图置信度低于 `0.55`，说明系统对当前判断还不够稳定，控制器会自动扩宽波束：

```text
目标波束宽度 = 基础波束宽度 + 14°
```

例如：

```text
classify_and_shadow 基础宽度 = 20°
低置信度修正 = +14°
最终目标波束宽度 = 34°
```

这就是截图中三部雷达都显示 `34.0°` 的原因。

控制器还会限制波束宽度在雷达能力范围内：

| 雷达 | 波束宽度范围 |
|---|---:|
| 岸基雷达 | `12° ~ 62°` |
| 舰载雷达 | `8° ~ 48°` |

#### 11.3.4 驻留时间如何生成

驻留时间同样先由任务动作决定，再根据置信度修正。

如果意图置信度低于 `0.55`，控制器会增加驻留时间：

```text
目标驻留时间 = 基础驻留时间 + 24 ms
```

例如：

```text
classify_and_shadow 基础驻留 = 135 ms
低置信度修正 = +24 ms
最终目标驻留 = 159 ms
```

这就是截图中 `驻留 159→159 ms` 的来源。

#### 11.3.5 波束转向速度如何生成

波束转向速度由雷达类型和任务优先级共同决定。

岸基雷达：

```text
转向速度 = 28 + 4 × priority
```

舰载雷达：

```text
转向速度 = 38 + 5 × priority
```

`classify_and_shadow` 的默认优先级为 `2`，因此：

```text
岸基雷达速度 = 28 + 4 × 2 = 36°/s
舰载雷达速度 = 38 + 5 × 2 = 48°/s
```

这对应截图中的：

```text
岸基：36.0°/s
舰01：48.0°/s
舰02：48.0°/s
```

#### 11.3.6 距离门如何生成

距离门根据雷达到预测目标位置的距离计算，并额外加入安全余量：

```text
距离门 = 预测目标距离 + 18 km
```

之后控制器会把距离门限制在雷达最大作用距离内：

| 雷达 | 最大距离门 |
|---|---:|
| 岸基雷达 | `185 km` |
| 舰 01 雷达 | `128 km` |
| 舰 02 雷达 | `132 km` |

由于岸基、舰 01、舰 02 的位置不同，它们到同一预测目标点的距离不同，因此面板中三部雷达的距离门也不同。

#### 11.3.7 跟踪强度如何生成

跟踪强度是前端展示用的归一化解释指标，用来概括当前控制策略的“跟踪聚焦程度”。

它由三部分构成：

```text
跟踪强度 = 0.38 × 波束聚焦程度
         + 0.42 × 驻留增强程度
         + 0.20 × 意图置信度
```

其中：

```text
波束越窄，波束聚焦程度越高；
驻留越长，驻留增强程度越高；
置信度越高，控制器越敢于增强精确跟踪。
```

因此，`强度 55%` 表示当前控制策略比常规监视更聚焦，但还没有进入最高优先级精跟状态。

### 11.4 当前截图结果的解释

截图中三部雷达都处于：

```text
classify_and_shadow / bounded_slew
```

说明系统当前判断目标需要“分类并伴随跟踪”，但控制器仍然受到转向速度约束，波束会平滑转动。

具体可以解释为：

```text
当前任务不是普通巡扫，也不是最高等级告警精跟；
系统希望三部雷达适度收窄波束，增加驻留时间，
提高目标分类与稳定跟踪能力；
由于当前意图置信度低于 0.55，
控制器自动将 classify_and_shadow 的 20° / 135 ms
修正为 34° / 159 ms，
以扩大搜索容错并增强观测积累。
```

岸基雷达和两部舰载雷达的速度不同，是因为舰载雷达被设定为更快的近距协同跟踪平台：

```text
岸基雷达：36°/s
舰载雷达：48°/s
```

三部雷达的距离门不同，是因为它们位于不同位置，到预测目标点的几何距离不同。
